# Smena — кабинет водителя и администратора

Веб-сервис для смен водителей IC Group: чек-лист смены, инструктаж по ТБ,
автопарк, история и отчёты. Общая база для всех устройств, работа с телефона.

## Стек

- **Next.js** (App Router) — интерфейс и API в одном проекте.
- **Supabase Postgres** — база данных, подключение обычной строкой `DATABASE_URL`.
- **Supabase Storage** — приватный бакет `shift-photos` для фото повреждений.
- **Vercel** — хостинг.
- Вход по **номеру телефона и PIN**, PIN хранится bcrypt-хэшем, сессия — в
  подписанной httpOnly-cookie на 30 дней со скользящим продлением.

## Решения, заложенные в схему

- **Водители и администраторы — одна таблица** `drivers`, различаются полем
  `role`. Отдельной регистрации нет: профили создаёт администратор, PIN по
  умолчанию — последние 4 цифры номера.
- **История смен неизменяема.** Завершённая смена хранит собственный снимок
  пунктов чек-листа (`shift_items`) вместе с текстом и подписью водителя на тот
  момент. Правки шаблона, переименование водителя и продажа машины не меняют
  того, что уже сдано.
- **Удаление того, на что ссылается история, — флагом `active`.** Автомобиль
  или водитель со сменами не удаляются (API отвечает 409), а выводятся из
  работы. Пункты чек-листа и вопросы теста — так же.
- **Правильные ответы теста не покидают сервер.** Водителю вопросы приходят без
  `correct_index`, ответы проверяет `lib/briefing.ts`.
- **Без действующего допуска по ТБ смена не закрывается** — проверка стоит и в
  интерфейсе (для удобства), и в `POST /api/shifts` (по факту).
- **Повторное завершение смены не создаёт дубль** — по ключу идемпотентности
  `client_request_id`.
- **Фото лежат в приватном бакете**, наружу уходят только подписанные ссылки с
  ограниченным сроком. Секретный ключ проекта читается только на сервере.
- **Вход защищён от подбора PIN**: 4 цифры — это 10 000 вариантов, поэтому
  после 5 неверных попыток вход закрывается на 15 минут. Сброс PIN
  администратором снимает блокировку сразу.
- **Черновик смены сохраняется на сервере** (`shift_drafts`) с задержкой в
  секунду после каждой правки: перезагрузка страницы, разряженный телефон или
  потерянная связь не стирают отмеченные пункты.
- **Фото уходит в хранилище сразу**, не дожидаясь конца смены: в черновике
  остаётся только путь к файлу. Снимки, которые в смену так и не попали
  (замечание сняли, черновик бросили), удаляются из бакета — иначе они копятся
  там навсегда.
- **Касса обязана сходиться.** Остаток не вводится, а считается: `начало +
  приход − расход − штрафы`. Одна формула на всё приложение
  (`cashBalance` в `lib/model.ts`), и сервер не принимает присланный остаток.
  Приход — отдельное поле: без него у водителя не было места для полученных
  денег, и в истории остались смены, где остаток не выводился из начала и
  расхода вовсе (начало 15 000, расход 40 000, «остаток» 50 000). Такие смены
  миграция пересчитывает: недостающий приход восстанавливается из самой
  арифметики.
- **Начало смены — это конец предыдущей.** `GET /api/shifts/opening` отдаёт
  остаток кассы водителя и одометр машины, и поля подставляются сами. Пробег
  больше 2000 км за смену не принимается — это опечатка в показаниях.
- **Сданную смену правит только администратор**, и она помечается
  `edited_at` / `edited_by_label`. Снимок чек-листа при этом не меняется:
  отметки и замечания — то, что водитель подтвердил сам.
- **Расход и штрафы смены сразу попадают в расходы автопарка** со ссылкой
  `shift_id`. По отдельности такие записи не удаляются (409): первичный
  документ — смена, и правятся они вместе с ней.
- **График — это закрытые смены, а не отдельный план.** Таблица `assignments`
  осталась в схеме ради уже заведённых записей, но ничем не используется:
  водитель фиксирует начало и завершение сам, и второй список ту же информацию
  только дублировал.
- **Черновик дублируется в телефоне** (`localStorage`): водитель работает в
  паркинге и в лифте, и пока связи нет, отметки должны оставаться целыми.
  При запуске берётся та копия, которая новее; отправка на сервер идёт сама,
  как только сеть вернулась.

## Локальный запуск

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Заполнить `.env.local`:
   ```bash
   npm run setup:env
   ```
   Скрипт спросит три значения (см. раздел «Настройка Supabase»), проверит их
   формат и сам сгенерирует `SESSION_SECRET`. Ввод не отображается, значения
   идут прямо в файл — не через историю команд и не через переписку. Файл можно
   заполнить и руками, взяв за основу `.env.example`.
3. Проверить, что настройки на месте и работают:
   ```bash
   npm run check:env
   ```
   Скрипт показывает состав строки подключения и длины секретов (сами значения
   не печатает), подключается к базе и проверяет, что приватный бакет
   `shift-photos` существует и действительно приватный.
4. Применить схему и начальные данные:
   ```bash
   npm run db:migrate
   npm run db:seed
   ```
5. Запустить:
   ```bash
   npm run dev
   ```

### Проверка на временной базе в Docker

Чтобы не трогать рабочую базу, можно поднять одноразовую:

```bash
docker run -d --name smena-test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=smena_test -p 55432:5432 postgres:17-alpine
```

Строку подключения к ней (`postgres://postgres:test@127.0.0.1:55432/smena_test`)
удобно положить в `.env.development.local` — этот файл перекрывает `.env.local`
только для `npm run dev`, а рабочие значения остаются на месте. Контейнер
с базой удаляется командой `docker rm -f smena-test`.

## Настройка Supabase

1. **Проект**: supabase.com → New Project.
2. **Строка подключения**: Connect → вкладка **Direct** (Connection string).
   Для Vercel берите **Transaction pooler** (порт 6543) — функции там
   короткоживущие, и режим транзакций держит меньше соединений к базе.
   Значение идёт в `DATABASE_URL`.
3. **Ключи для Storage**: Connect → вкладка **Server** (или Project Settings →
   API keys) → `SUPABASE_URL` и `SUPABASE_SECRET_KEY` (значение `sb_secret_…`).
   `SUPABASE_PUBLISHABLE_KEY` и `SUPABASE_JWKS_URL` не нужны: они для проверки
   токенов Supabase Auth, а вход у нас свой — по телефону и PIN. Пакет
   `@supabase/server` тоже не нужен — в базу ходим через `pg`, в Storage
   обычным fetch.
4. **Бакет**: Storage → New bucket → имя `shift-photos`, галочку **Public не
   ставить**.
5. **Секрет сессии**:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   Значение идёт в `SESSION_SECRET`.

Пока `SUPABASE_URL` и `SUPABASE_SECRET_KEY` не заданы, всё работает,
кроме загрузки фото: `/api/photos` отвечает 503, а `/api/settings` сообщает
интерфейсу `photoUploadEnabled: false`.

## Первый администратор

Создаётся командой, а не формой регистрации: форма «создать первого админа» на
публичном адресе открыта для любого, кто зайдёт раньше вас.

```bash
ADMIN_PHONE="+7 707 555 90 11" ADMIN_LAST_NAME="Бекова" ADMIN_FIRST_NAME="Гульмира" npm run db:seed
```

PIN по умолчанию — последние 4 цифры номера (можно задать свой в `ADMIN_PIN`).
Дальше администратор заводит автомобили и водителей из кабинета.

`npm run db:seed` можно запускать повторно: справочники заполняются только если
пусты, администратор создаётся только если такого номера ещё нет.

## Деплой на Vercel

1. Залить проект в GitHub-репозиторий.
2. vercel.com → New Project → импортировать репозиторий.
3. Settings → Environment Variables: `DATABASE_URL`, `SESSION_SECRET`,
   `SUPABASE_URL`, `SUPABASE_SECRET_KEY`.
4. Применить схему к продакшн-базе:
   ```bash
   DATABASE_URL="<строка продакшн-БД>" npm run db:migrate
   DATABASE_URL="<строка продакшн-БД>" ADMIN_PHONE="<номер>" npm run db:seed
   ```
5. Дальше деплой идёт автоматически при пуше в `master`.

## Что стоит знать при эксплуатации

- **Первый вход**: администратор заходит по своему номеру и PIN, добавляет
  автомобили (Автопарк → Добавить), затем водителей (Водители → Добавить).
  После создания профиля система показывает PIN водителя — его нужно передать
  лично; в базе хранится только хэш.
- **Водитель забыл PIN**: Водители → карточка → сброс PIN. Он вернётся к
  последним 4 цифрам номера, блокировка снимется.
- **Увольнение**: профиль со сменами не удаляется (иначе пропадёт автор
  отчётов) — он отключается, и доступ пропадает сразу, даже если водитель уже
  вошёл.
- **Правка чек-листа** применяется к новым сменам сразу, сданные смены
  остаются в том виде, в каком их закрыли.
- **Водитель ошибся в кассе или одометре**: Смены → смена → «Касса» →
  «Исправить». Остаток пересчитывается сам, расходы автопарка обновляются, а в
  отчёте и выгрузке остаётся пометка, кто и когда правил.
- **Параметры теста** (сколько вопросов, сколько верных, срок действия) и номер
  получателя сводки: Настройки → Параметры.
- **Выгрузка** (Смены → Excel) — книга из трёх листов: «Смены» со строкой
  итогов, «Касса» журналом по каждой смене и «Замечания» построчно. Даты и
  суммы уходят числами, поэтому в Excel по ним работают сортировка и формулы.
- **На телефоне** кабинет можно добавить на домашний экран — откроется как
  приложение, без адресной строки.

## Отправка в WhatsApp

Кнопка открывает чат с готовым текстом сводки, отправляет водитель сам —
ссылка `wa.me` («Click to Chat»), бесплатно и без регистрации. Если в
настройках указан номер получателя, чат открывается сразу с ним.

Статичной ссылки «открыть определённую группу с готовым текстом» в публичном
API WhatsApp не существует: `wa.me/<номер>` открывает только личный чат, а
ссылка-приглашение в группу не умеет подставлять текст. Без номера открывается
выбор чата, где группа доступна одним нажатием. Автоматическая отправка
возможна только через WhatsApp Business Cloud API — платно и с верификацией
бизнес-аккаунта.
