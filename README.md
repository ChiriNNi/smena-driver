# Smena — кабинет водителя и администратора

Веб-сервис для смен водителей IC Group: чек-лист смены, инструктаж по ТБ,
автопарк, история и отчёты. Общая база для всех устройств, работа с телефона.

## Стек

- **Next.js** (App Router) — интерфейс и API в одном проекте.
- **Supabase Postgres** — база данных, подключение обычной строкой `DATABASE_URL`.
- **Supabase Storage** — приватный бакет `shift-photos` для фото повреждений.
- **Vercel** — хостинг.
- Вход по **номеру телефона и PIN**, PIN хранится bcrypt-хэшем, сессия — в
  подписанной httpOnly-cookie на 30 дней со скользящим продлением.

## Решения, заложенные в схему

- **Водители и администраторы — одна таблица** `drivers`, различаются полем
  `role`. Отдельной регистрации нет: профили создаёт администратор, PIN по
  умолчанию — последние 4 цифры номера.
- **История смен неизменяема.** Завершённая смена хранит собственный снимок
  пунктов чек-листа (`shift_items`) вместе с текстом и подписью водителя на тот
  момент. Правки шаблона, переименование водителя и продажа машины не меняют
  того, что уже сдано.
- **Удаление того, на что ссылается история, — флагом `active`.** Автомобиль
  или водитель со сменами не удаляются (API отвечает 409), а выводятся из
  работы. Пункты чек-листа и вопросы теста — так же.
- **Правильные ответы теста не покидают сервер.** Водителю вопросы приходят без
  `correct_index`, ответы проверяет `lib/briefing.ts`.
- **Без действующего допуска по ТБ смена не закрывается** — проверка стоит и в
  интерфейсе (для удобства), и в `POST /api/shifts` (по факту).
- **Повторное завершение смены не создаёт дубль** — по ключу идемпотентности
  `client_request_id`.
- **Фото лежат в приватном бакете**, наружу уходят только подписанные ссылки с
  ограниченным сроком. `service_role`-ключ используется только на сервере.

## Локальный запуск

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Скопировать `.env.example` в `.env.local` и заполнить (см. следующий раздел).
3. Применить схему и начальные данные:
   ```bash
   npm run db:migrate
   npm run db:seed
   ```
4. Запустить:
   ```bash
   npm run dev
   ```

### Проверка на временной базе в Docker

Чтобы не трогать рабочую базу, можно поднять одноразовую:

```bash
docker run -d --name smena-test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=smena_test -p 55432:5432 postgres:17-alpine
```

Строку подключения к ней (`postgres://postgres:test@127.0.0.1:55432/smena_test`)
удобно положить в `.env.development.local` — этот файл перекрывает `.env.local`
только для `npm run dev`, а рабочие значения остаются на месте. Контейнер
с базой удаляется командой `docker rm -f smena-test`.

## Настройка Supabase

1. **Проект**: supabase.com → New Project.
2. **Строка подключения**: Project Settings → Database → Connection string →
   режим **Session pooler**. Значение идёт в `DATABASE_URL`.
3. **Ключи для Storage**: Project Settings → API → `Project URL` и
   `service_role` → `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.
4. **Бакет**: Storage → New bucket → имя `shift-photos`, галочку **Public не
   ставить**.
5. **Секрет сессии**:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   Значение идёт в `SESSION_SECRET`.

Пока `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` не заданы, всё работает,
кроме загрузки фото: `/api/photos` отвечает 503, а `/api/settings` сообщает
интерфейсу `photoUploadEnabled: false`.

## Первый администратор

Создаётся командой, а не формой регистрации: форма «создать первого админа» на
публичном адресе открыта для любого, кто зайдёт раньше вас.

```bash
ADMIN_PHONE="+7 707 555 90 11" ADMIN_LAST_NAME="Бекова" ADMIN_FIRST_NAME="Гульмира" npm run db:seed
```

PIN по умолчанию — последние 4 цифры номера (можно задать свой в `ADMIN_PIN`).
Дальше администратор заводит автомобили и водителей из кабинета.

`npm run db:seed` можно запускать повторно: справочники заполняются только если
пусты, администратор создаётся только если такого номера ещё нет.

## Деплой на Vercel

1. Залить проект в GitHub-репозиторий.
2. vercel.com → New Project → импортировать репозиторий.
3. Settings → Environment Variables: `DATABASE_URL`, `SESSION_SECRET`,
   `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
4. Применить схему к продакшн-базе:
   ```bash
   DATABASE_URL="<строка продакшн-БД>" npm run db:migrate
   DATABASE_URL="<строка продакшн-БД>" ADMIN_PHONE="<номер>" npm run db:seed
   ```
5. Дальше деплой идёт автоматически при пуше в `master`.

## Отправка в WhatsApp

Кнопка открывает чат с готовым текстом сводки, отправляет водитель сам —
ссылка `wa.me` («Click to Chat»), бесплатно и без регистрации. Если в
настройках указан номер получателя, чат открывается сразу с ним.

Статичной ссылки «открыть определённую группу с готовым текстом» в публичном
API WhatsApp не существует: `wa.me/<номер>` открывает только личный чат, а
ссылка-приглашение в группу не умеет подставлять текст. Без номера открывается
выбор чата, где группа доступна одним нажатием. Автоматическая отправка
возможна только через WhatsApp Business Cloud API — платно и с верификацией
бизнес-аккаунта.
